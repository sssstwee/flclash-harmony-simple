# 小猫AI代理

基于 [tljk/FlClash-ohos 的 v0.8.94-ohos 分支](https://github.com/tljk/FlClash-ohos/tree/v0.8.94-ohos)，上游基线 `017c08b8f842fef37ffb3220605b2477380a6dc4`。保留 GPL-3.0 许可和上游版权；本分支并非 FlClash 官方发行版。

目标设备为用户提供的 Pura X View / HarmonyOS 7；该设备兼容性和后台稳定性需要真机验证。

鸿蒙包名为 `com.follow.clash.simple`，与上游独立安装；签名配置需要对应这个包名。Flutter/ArkTS 内部 MethodChannel 名称沿用上游，避免改变平台通信协议。

## 日常操作

1. 使用管理员提供的用户名和密码登录，应用自动下载线路配置。
2. 点击「连接」，自动选择可用线路；首次使用需要允许系统 VPN 授权。
3. 点击「断开」停止代理。

登录后首页显示国内直连与国外代理的检查结果、连接／断开按钮、当前线路、流量和退出登录。没有订阅或规则编辑入口；仅安全的手动选择组可显示切换节点按钮，正常使用无需手动选线。登录及每次连接时自动从服务端获取配置；配置由管理员同步到 D1，手机端无需导入订阅。默认内网和国内域名/IP 直连，一般国外流量走自动选择的代理线路，无需添加规则；订阅中明确的服务、域名、规则集和广泛地域策略均保留，例如要求中国流量使用代理的 GEOIP,CN／GEOSITE,cn 规则；国内直连默认值只补充未配置的策略。默认国内域名使用国内 DNS，内网域名使用系统 DNS，同时保留已有的分域 DNS 策略；IPv4/IPv6 私有地址直连。复用包内的 [Mihomo GeoSite/GeoIP 数据](https://github.com/MetaCubeX/meta-rules-dat)，不依赖另行下载规则集。分流按目标域名和 IP 判断，不按应用名称判断。

鸿蒙启动时统一应用内置网络和 VPN 默认值，DNS 由应用管理，语言和外观跟随系统；关闭局域网代理共享及外部控制器。原有订阅保留，但日常连接使用服务端统一配置；旧附加规则、自定义覆写和脚本不参与连接。退出登录后停止代理并清理远程配置缓存。登录会话由原生安全存储插件加密保存，密码不写入应用配置。首次连接／断开过程中禁用重复操作；后台健康检查或自动重连时仍可点击断开，以取消连接意图和后续重试。动画遵循系统减少动画设置，状态变化提供无障碍播报。布局可滚动、限制最大内容宽度，以适配窄屏和展开后的折叠屏。

服务端使用 [Better Auth](https://github.com/better-auth/better-auth) 与 Cloudflare Workers / D1，部署和账号管理见 [backend/README.md](backend/README.md)。Cloudflare 托管认证及配置，不提供代理节点。重新启动应用后需要点击连接，登录过期后需要重新登录。

## 自动选线

- 应用生成独立的自动测速组，只包含真实代理节点及展开后的代理集，不把可能指向直连的嵌套订阅组用作默认国外线路。
- Mihomo 内核持续维护自动选线，前台也会分别检查国内直连和国外代理。连接和恢复过程不把自动组固定在某一个节点。
- 自动组每 60 秒执行严格 HTTPS 204 检查，单次超时 5 秒。代理集保留原来的下载来源和更新周期，健康检查统一设置。
- 空代理集、过滤后无节点或无可用线路时安全失败，不以 COMPATIBLE／DIRECT 冒充可用代理。规则末尾有拒绝兜底，避免不支持的 UDP 从默认国外代理意外回落直连。
- 分流保留订阅的明确策略，包括服务、域名、规则集以及 GEOIP,CN／GEOSITE,cn 等广泛地域策略。未配置策略时才补充国内直连默认值，一般国外流量使用自动代理。订阅可明确要求国内流量使用代理，或要求特定目标直连或拒绝，需要按该订阅实际规则验收。
- 连接时使用规则模式并开启 VPN；前台恢复有退避和冷却，后台自动选线依赖内核和系统保持 VPN 服务存活。

## GitHub 验证与构建

使用上游 CI 指定的鸿蒙 Flutter SDK：`CPF-Flutter/flutter_flutter` 的 `3.44.9+ohos-0.0.1-canary1`，以及仓库的 `.github/flutter_ohos.patch`。普通 Flutter SDK 不支持此项目的 `Platform.isOhos` 与 `TargetPlatform.ohos`。

推送到 `main` 或手动运行 Actions 的 **小猫AI代理** 工作流，会检查服务端类型和认证测试，并依次安装应用依赖、静态检查、运行全部 Flutter 测试、编译鸿蒙 Go 内核并构建 HAP / APP。构建产物与 SHA-256 校验文件保存在对应运行的 Artifacts 中，保留 14 天。

本自动适应修复的独立分支 `dot/harmony-auto-adapt-20261014-0519` 首轮 PR 检查只做验证，不打包。只有同一提交首轮完整验证成功后，明确重跑该 PR 的 build 作业或提供成功验证记录手动运行，才允许独立构建；其他修复分支不参与。包名包含 `xiaomao-ai-proxy` 和提交短 SHA，随附完整提交、验证/打包执行次数及校验和，便于与并行实现区分。

工作流沿用上游 CI 的 SDK 和工具链，输出未签名 HAP。安装前需要使用与 `com.follow.clash.simple` 对应、包含目标手机 UDID 的 HarmonyOS 调试证书和 profile 签名；证书、私钥和订阅链接不得提交进公开仓库。真机的 VPN 授权仍需设备所有者完成。

Profile 的 ACL 授权需包含 `ohos.permission.KEEP_BACKGROUND_RUNNING_SYSTEM`，以支持手机后台任务。简洁版移除了分应用选择及旧媒体访问的权限声明。

## 真机验收

- 登录成功／失败、登录过期、服务端不可达、全部节点超时、取消 VPN 授权、退出登录后配置访问失效。
- 手机折叠/展开、较大字号、重复点击、后台锁屏、Wi-Fi/移动网络切换。
- 首次连接与重新启动后，规则流量、DNS、实际外网访问和断开后网络恢复。
- 上游 [鸿蒙 7 全局模式联网反馈 #11](https://github.com/tljk/FlClash-ohos/issues/11) 尚未解决。本分支使用规则模式；这不代表已修复该问题，也不代表所有鸿蒙 7 设备已验证。

## 连接状态与限制

- 首页只有在服务运行、国内直连和国外代理两项检查均通过时才显示「已连接」。仅有运行计时、流量计数或单个节点延迟不会被当作连接成功。
- 首页分别显示「正在检查连接」「正在自动重连」「部分网络不可用」「网络不可用」等状态，并区分国内直连与国外代理哪一项检查失败。账号过期需要重新登录；网络登录提示与账号登录是两种独立状态。
- 仅在有明确的网络登录证据时提示「当前网络可能需要登录」。一般超时或两项检查失败不能证明 Wi-Fi 有登录页面。
- 使用已保存配置并不代表网络离线，因此缓存提示与网络健康状态分开显示。中英文状态和错误提示随当前界面语言更新。
- 自动恢复会在仍要求连接且条件允许时重试；主动断开或退出登录会取消重试。应用处于后台、系统限制或网络不可用时，无法保证及时恢复。网络切换可能中断已有连接，不能承诺无感切换或零丢包。
- 检查只覆盖指定测试目标和当时的网络，不能证明每个网站、应用、DNS、UDP 或 IPv6 都正常。默认分流会补充并约束原订阅规则和 DNS 默认值，同时保留具体例外和广泛地域策略；国内直连检查只代表该测试目标的直连可达性，不代表所有国内流量均直连或可达。有自定义广告过滤、企业域名或专用路由时，仍需单独验收兼容性。
- 连接仍需要有效账号、可用代理节点、手机网络和设备所有者允许首次系统 VPN 授权。应用不能绕过系统授权或替代管理员开通账号。

上述检查和自动恢复必须继续完成真机验收，尤其是 VPN 授权、Wi-Fi／蜂窝切换、后台锁屏、DNS／IPv6／UDP 和断开后的网络恢复。自动化测试通过不代表这些手机场景已经验证。
